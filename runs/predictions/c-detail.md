# C 故障注入的数值预测补充（测量前）

固定3个实例、167rps，每个约55.67rps。

- 停止：若scaler每秒巡视先发现退出并移除，预计约0–1s判定，对应最多约56个在此期间新分配的失败请求；若只依赖默认健康检查，连接拒绝快速失败，三次失败约2–3s，对应约111–167个。
- 卡住20s：请求/readyz会等待500ms超时；1s周期、fall3，预计约2.5–3.5s判定，期间约139–195个分配到故障实例的请求失败。实测计数按计划发送秒归属，尚在途和采样边界会造成偏差。
- 全部暂停2s：默认fall3可能尚未连续失败三次就恢复；灵敏参数500ms/200ms/fall1预计0.2–0.7s判定全部down，恢复后还要连续两次成功，可能至暂停开始后约2.5–3s才全部恢复。灵敏设置可能产生数百个即时503，默认可能只有边缘超时；这是预测，不预填实测。
- 变慢：在C1正常阶段先实测每实例CPU用量U，再取约U/0.85的配额。预计业务排队和p99增加，但轻量/readyz仍通过。离群摘除预计改善总体尾延迟，代价是剩下两实例负载增加、被摘除实例周期性恢复后可能再次离群。
